# IPDaddChart — Add ยา Continue ผู้ป่วยใน (HosXP) แบบกดปุ่มเดียว

เว็บแอปรันในเครื่อง (localhost) ที่ดึงรายชื่อผู้ป่วยที่ admit อยู่จากฐานข้อมูล HOSxP
(หรืออัพโหลด Excel) แล้วให้โรบอท (pywinauto) คีย์ใน HosXP แทนคน วนจนครบทุกคน
พร้อมเก็บ log ทุกการรันลง SQLite และกันคีย์ซ้ำ

**ลำดับที่โรบอททำต่อคนไข้ 1 คน** (ตรงกับที่ทำด้วยมือ) ในหน้า **IPD Medication Profile**:

0. ถ้าหน้าจอยังค้างอยู่ที่คนก่อนหน้า → กดปุ่ม **"เลือกใหม่"** กลับไปหน้าเลือกคนไข้ก่อน
1. คีย์ **HN** ลงช่องในกรอบ "เลือกคนไข้" แล้ว Enter
2. ตรวจกรอบ "ข้อมูลผู้ป่วย" ว่า HN/AN ตรงกับคนที่ตั้งใจ — ไม่ตรง = ไม่ทำต่อ
3. กดปุ่ม **New**
4. กดปุ่ม **Add Chart F5**
5. กด **F9** บันทึก
6. popup ยืนยัน → **Enter**
7. วนคนถัดไป

## ติดตั้ง (ครั้งแรกต่อเครื่อง)

1. ติดตั้ง Python 3.11+ (ติ๊ก Add to PATH ตอนติดตั้ง)
2. ดับเบิลคลิก `setup.bat` — สร้าง venv, ลงไลบรารี, สร้าง `config\settings.json` ให้อัตโนมัติ
3. เปิด `run.bat` แล้วไปหน้า **ตั้งค่า** ใส่:
   - `hosxp_db.user` / `hosxp_db.password` — บัญชีอ่านฐานข้อมูล HOSxP (โปรแกรมใช้ SELECT อย่างเดียว)
   - `hosxp_app.username` / `hosxp_app.password` — บัญชี login โปรแกรม HosXP ของเครื่องนั้น

## selector ที่ map ไว้แล้ว (จาก HosXP 3.68.6.13 เครื่อง PHAMACY14)

ค่าเริ่มต้นใน `config\default_settings.json` map ไว้ให้แล้วทั้งหมด:

| สิ่งที่ใช้ | selector |
|---|---|
| ฟอร์ม IPD | `TIPDRxForm` title `IPD Medication Profile` |
| ช่องคีย์ HN | ในกรอบ `TcxGroupBox 'เลือกคนไข้'` → `TdxEdit` ตัวที่ 0 |
| กรอบตรวจสอบคนไข้ | `TcxGroupBox 'ข้อมูลผู้ป่วย'` (แสดง HN 7 หลักและ AN 9 หลักจริงหลังโหลด) |
| แท็บยา | `TcxTabSheet 'สั่งยา'` |
| ปุ่มที่กด | `TcxButton 'New'` แล้ว `TcxButton 'Add Chart F5'` |
| บันทึก | ปุ่มลัด `{F9}` แล้ว popup ยืนยัน → `{ENTER}` |

**ถ้าย้ายไปเครื่องที่หน้าจอไม่เหมือนกัน** ให้สแกนใหม่:

1. เปิด HosXP → เปิดหน้า IPD Medication Profile → เรียกคนไข้ขึ้นมา 1 คน
2. ดับเบิลคลิก **`inspect_hosxp.bat`** (dump ทุก control ลง `data\hosxp_controls.txt`)
   หรือ **`probe_ipd.bat`** (ดูเฉพาะช่องคีย์คนไข้ + เมนูคลิกขวาบนตารางยา)
3. แก้ selector ที่หน้า "ตั้งค่า" ในหัวข้อ `robot.ipd_form` และ `robot.steps.action_buttons`
   (`action_buttons` เป็นลิสต์ กดตามลำดับ เพิ่ม/ลดปุ่มได้)

## ⚠️ ต้องรันด้วยสิทธิ์ผู้ดูแลระบบ (Administrator)

ตัวโปรแกรม HosXP (`hosmy.exe`) ประกาศ `requireAdministrator` ไว้ในตัวเอง จึงรันด้วยสิทธิ์สูงเสมอ
Windows จะ**บล็อกไม่ให้โปรแกรมสิทธิ์ต่ำส่งคีย์บอร์ด/เมาส์ไปยังหน้าต่างของโปรแกรมสิทธิ์สูง**
ถ้ารัน IPDaddChart แบบผู้ใช้ธรรมดา จะเจอสองอาการนี้:

- เปิด HosXP ไม่ได้ → `CreateProcess error 740: The requested operation requires elevation`
- ต่อให้เปิด HosXP ค้างไว้เอง โรบอทก็จะกดอะไรไม่เข้าเลย **โดยไม่มี error** (อันตรายที่สุด)

`run.bat` จึงขอสิทธิ์ผู้ดูแลระบบให้อัตโนมัติ — จะมีหน้าต่าง UAC เด้งขึ้นมาให้กด **Yes** ทุกครั้งที่เปิด
(ถ้าไม่ขึ้น ให้คลิกขวาที่ `run.bat` → Run as administrator)
หน้าเว็บจะขึ้นแถบแดงและปิดปุ่ม "เริ่มคีย์" ให้เองถ้าสิทธิ์ไม่พอ

## ใช้งานประจำวัน

1. เปิด HosXP ทิ้งไว้ (login แล้ว) และเปิดหน้า IPD Medication Profile ค้างไว้
2. ดับเบิลคลิก `run.bat` → กด Yes ที่ UAC → เบราว์เซอร์เปิด http://127.0.0.1:8770
3. กด **⬇ ดึงจากฐานข้อมูล HOSxP** → เลือกตึกที่ช่อง **"แสดง ward"** (ตั้งต้นยังไม่เลือก
   จะไม่กางคนไข้ทั้งโรงพยาบาลออกมา) เลือก "ทุก ward" ได้ถ้าต้องการดูรวม
   **โปรแกรมจะคีย์เฉพาะคนที่แสดงอยู่ในตารางเท่านั้น** — คนใน ward อื่นถูกกรองออกไปแล้ว
   ติ๊กหัวกลุ่มเพื่อเลือกทั้ง ward หรือติ๊กออกเป็นรายคน / กด ▾ เพื่อย่อ ward ที่ไม่ต้องคีย์
   (แถวค้างที่ไม่ได้นอนจริงถูกกรองทิ้งตั้งแต่ต้น — ดู "ตัวกรองผู้ป่วยที่ admit อยู่จริง")
   คอลัมน์ **รายการยา** บอกว่าจะมียา continue ยกมากี่รายการ — `0 — จะได้ No Item` คือคนที่
   ยังไม่มีคำสั่งยา กดไปก็ไม่มีอะไรถูกบันทึก ติ๊กออกได้เลย (หัว ward สรุปให้ว่าตึกนั้นมีกี่คน)
4. กด **▶ เริ่มคีย์** — ครั้งแรกของวันแนะนำติ๊ก "โหมดทดสอบ" ก่อน 1 รอบ แล้วค่อยรันจริง
5. ระหว่างโรบอททำงาน **อย่าใช้เมาส์/คีย์บอร์ด** — กด ■ หยุด ได้ตลอด (จะจบหลังคนปัจจุบัน)
6. ดูผลย้อนหลังที่หน้า "ประวัติการรัน" (คลิกที่แถวเพื่อดู log ทุกบรรทัดของรอบนั้น)

## 🔴 รอบแรกที่คีย์จริง ต้องมีเภสัชกรนั่งดู (commissioning)

โรบอทตั้งค่ามาแบบ **"dialog ไหนไม่รู้จัก = ไม่กด"** ตั้งแต่ต้น เพราะปุ่ม Enter คือปุ่ม default
ซึ่งแปลว่า "ตกลง" — ถ้า HosXP เด้งคำเตือน **แพ้ยา / ยาตีกัน / ยาซ้ำซ้อน** ขึ้นมา
การกด Enter คือการยืนยันสั่งยาทับคำเตือนแทนเภสัชกร ซึ่งห้ามเด็ดขาด

กล่องยืนยันหลังกดบันทึกของเครื่องนี้ map ไว้ให้แล้ว (`robot.steps.confirm_dialog`):

```json
{ "title_re": "^Confirm$", "message_re": "",
  "yes_button": { "class_name": "Button", "title_re": "^&?(Yes|ใช่|ตกลง|OK)$" } }
```

อ่านว่า: ยอมกดปุ่ม **Yes** เฉพาะกล่องที่หัวเรื่องเป็น `Confirm` และ **อ่านข้อความในกล่องไม่ได้เลย** เท่านั้น
ถ้าจู่ ๆ อ่านข้อความได้ = ไม่ใช่กล่องเดิม = โรบอทหยุดทันทีให้เภสัชกรอ่านเอง

ข้อความจริงในกล่องคือ **"Please confirm save"** (เห็นได้จากภาพหลักฐานที่เก็บอัตโนมัติ)
เดิมอ่านไม่ได้จึงตั้ง `message_re` เป็นค่าว่าง = "ต้องไม่มีข้อความ" ซึ่งเป็นการตรวจที่อ่อนมาก
ตอนนี้อ่านได้แล้วด้วย UI Automation จึงตรวจข้อความตรง ๆ ได้ = **แน่นหนากว่าเดิมมาก**

> ⚠️ ถ้าเครื่องไหนใช้ UI Automation ไม่ได้ ระบบจะยังกดต่อโดยอาศัยหัวเรื่อง + ชุดปุ่ม
> (เท่ากับระดับความปลอดภัยเดิม) แต่จะเขียนคำเตือนลง log ทุกครั้งว่า "ตรวจข้อความไม่ได้"
> และเก็บภาพกล่องยืนยัน 2 ใบแรกของทุกรอบไว้ที่ `data\scans\` ให้ตรวจย้อนหลังได้เสมอ

ถ้าเครื่องอื่นกล่องยืนยันมีข้อความอื่น ให้ใส่ข้อความนั้นที่ `message_re`
— **อย่าใช้แค่คำว่า "บันทึก" หรือ "ยืนยัน"** เพราะคำเตือนแพ้ยาก็มีคำว่า "…ต้องการบันทึกหรือไม่" เหมือนกัน

### dialog อื่น ๆ ระหว่างทาง

ตั้งกฎได้ที่ `robot.popups.rules` — จับได้ 2 แบบ:
`match` (ข้อความในกล่อง — ต้องเจาะจง) หรือ `class_name` (ชื่อคลาสหน้าต่าง — ใช้กับหน้าต่างที่ไม่ใช่ dialog)
แล้วระบุ `action`:

| action | ความหมาย |
|---|---|
| `skip_patient` | ปิด dialog แล้ว**ข้ามคนนี้** ทำคนถัดไปต่อ (คนที่ข้ามยังไม่ถูกนับว่าทำแล้ว รอบหน้ากลับมาทำให้เอง) |
| `click` | ปิด dialog แล้วทำต่อกับคนเดิม |
| `halt` | หยุดทั้งงาน |

กฎที่ตั้งมาให้แล้ว 4 ข้อ:

| จับจาก | คือ | ทำอะไร |
|---|---|---|
| `Someone using this patient record` | มีคนอื่นเปิดเวชระเบียนคนนั้นค้างอยู่ | กด OK แล้ว**ข้ามคนนั้น** (คีย์ทับตอนคนอื่นแก้อยู่เสี่ยงข้อมูลชนกัน — รอบหน้าระบบทำให้เอง) |
| `No Item` | คนไข้ไม่มียา continue ให้ยกมา | กด OK แล้ว**ข้ามคนนั้น** — ไม่มีอะไรถูกบันทึก จึงไม่ติดธง "ต้องตรวจเอง" |
| `Select new patient` | ถามหลังบันทึกเสร็จว่าจะเลือกคนใหม่ไหม | กด Yes เพื่อกลับหน้าเลือกคนไข้ |
| คลาส `TPtNoteViewForm` | หน้าต่าง Note ของคนไข้ที่เด้งมาเอง | กด "ปิด" ก่อนทำงานต่อ (ทุกกรณี) |

หน้าต่าง Note จับด้วย**ชื่อคลาส ไม่ใช่ข้อความ** เพราะเนื้อ Note เป็นข้อมูลทางคลินิกที่อาจมีคำไปชนกฎคำเตือน
(เช่น Note ที่เขียนว่า "ผู้ป่วยกำลังตั้งครรภ์") และระบบ**ไม่บันทึกเนื้อ Note ลง log** — บอกแค่ว่าเจอและปิดให้แล้ว

> ⚠️ **ชื่อคลาส ≠ หัวเรื่องหน้าต่าง** (บทเรียนจริง run 324) — หน้าต่างนี้มีหัวเรื่องว่า `PtNoteViewForm`
> แต่ชื่อคลาสจริงคือ `TPtNoteViewForm` (Delphi ขึ้นต้นด้วย T เสมอ) กฎที่ตั้งจากหัวเรื่องจึงหาไม่เจอเลยสักครั้ง
> โรบอทไปเจอเอาตอนกด New ไปแล้ว = ชาร์ตค้าง = ต้องหยุดทั้งงาน
> กฎจึงใช้ `class_name_re` เป็น `^T?PtNoteViewForm$` ให้ครอบคลุมทั้งสองแบบ
> **เวลาตั้งกฎใหม่ ให้ดูชื่อคลาสจากไฟล์ `data\scans\dialog_*.txt` เสมอ อย่าเดาจากหัวเรื่องบนจอ**

dialog ที่ไม่เข้ากฎใด ๆ และไม่อยู่ใน `robot.popups.allow` จะหยุดงานเสมอ พร้อมเขียนข้อความนั้นลง log ให้อ่าน

### 🔍 กล่องของ HosXP ต้องอ่านด้วย UI Automation เท่านั้น

**อาการ** (log จริง 3–5 ส.ค. 2569): ทุก dialog อ่านได้แค่**หัวเรื่องกับชื่อปุ่ม** ข้อความข้างในว่างเปล่าเสมอ
กฎที่จับจากข้อความจึงไม่ทำงานเลยสักข้อ และโรบอทหยุดทั้งที่เป็นกล่องธรรมดา

| อ่านได้ (วิธีเดิม) | ของจริงบนจอ |
|---|---|
| `Warning \| OK` | Someone using this patient record |
| `:: HOSxP :: … \| OK` | No Item !!! |
| `Confirm \| &Yes \| &No` | Rx-Queue : 283 / Select new patient ? |

**สาเหตุ** — เจอจากภาพหลักฐาน `data\scans\dialog_20260805_113255_601.*` ที่เก็บอัตโนมัติตอนรันจริง:
โครงสร้างกล่องมี control 17 ตัวชื่อ `DirectUIHWND`, `CtrlNotifySink`, `SysLink`
= กล่องนี้เป็น **Task Dialog ของ Windows** ไม่ใช่ MessageBox ธรรมดา
ตัวหนังสืออยู่ในชั้น DirectUI ซึ่งไม่มี control ให้ถาม `WM_GETTEXT` จึงคืนค่าว่างตลอด

**พิสูจน์** — สร้างกล่อง Task Dialog ที่รู้ข้อความล่วงหน้า แล้วอ่านเทียบกัน:

| วิธีอ่าน | ผล |
|---|---|
| `WM_GETTEXT` (เดิม) | `''` |
| **UI Automation** | `'Rx-Queue : 283\nSelect new patient ?'` — **0.04 วินาที** ✅ |

**วิธีแก้** — `read_dialog()` อ่านด้วยวิธีเดิมก่อน ถ้าได้ค่าว่างจึงอ่านซ้ำด้วย UI Automation (`uia_text.py`)
ตอนนี้อ่านได้ทุกกล่อง กฎทั้งหมดกลับมาทำงานตามที่ออกแบบไว้ รวมทั้ง**แยก `No Item !!!` (ข้ามได้)
ออกจาก `บันทึกไม่สำเร็จ` (ต้องหยุด) ได้แล้ว** ซึ่งเดิมแยกไม่ออกเลย

> UIA อ่านได้เฉพาะกล่องมาตรฐานของ Windows ส่วนหน้าต่างของ Delphi เอง
> (เช่น `TDrugInteractionAlertForm`) UIA อ่านไม่ได้ แต่วิธีเดิมอ่านได้อยู่แล้ว — สองวิธีเสริมกันพอดี

**ทางสำรองถ้าเครื่องไหนใช้ UIA ไม่ได้**: กฎจับจาก **"รูปพรรณ" ของกล่อง** (`dialog`: คลาส + หัวเรื่อง + ชุดปุ่ม)
ใช้ได้เฉพาะเมื่อครบทุกข้อ — ①อ่านข้อความไม่ได้เลยทั้งสองวิธี (ถ้าอ่านได้แต่ไม่ตรงกฎ = คนละกล่อง **ห้ามเดา**)
②อยู่ในจังหวะที่ระบุใน `contexts` ③`require_after_save` = ต้องเกิดหลังโรบอทกดบันทึกสำเร็จในรอบนั้นแล้ว
(กล่องที่ค้างอยู่ก่อน = ไม่ใช่ของเรา อาจเป็นกล่องยืนยันการลบที่คนอื่นเปิดค้างไว้)
ทุกครั้งที่กฎนี้ทำงานจะเก็บภาพไว้เป็นหลักฐานเสมอ

### หลักฐานเวลาโรบอทหยุด (`data\scans\`)

ทุกครั้งที่หยุดเพราะ dialog ที่ไม่รู้จัก ระบบจะเก็บให้อัตโนมัติ:
`dialog_<เวลา>.txt` (โครงสร้างกล่อง: คลาส/ปุ่ม/ขนาด/ID) และ `dialog_<เวลา>.png` (**ภาพหน้าจอของกล่องนั้น**)
เปิดภาพดูแล้วจะรู้ทันทีว่า HosXP ขึ้นอะไร แล้วเอาไปตั้งกฎต่อได้ — ไฟล์อยู่ในเครื่องนี้เท่านั้น ไม่ส่งออกไปไหน
(ภาพอาจมีข้อมูลคนไข้ ควรลบทิ้งเมื่อไม่ใช้แล้ว)

## ความปลอดภัยที่ออกแบบไว้

- **ไม่เขียนฐานข้อมูลตรง ๆ เด็ดขาด** — ทุกอย่างผ่านหน้าจอ HosXP เพื่อให้ logic ของโปรแกรมทำงานครบ
- **กันคีย์ซ้ำ**: คนที่คีย์สำเร็จแล้วจะขึ้น "ทำแล้ว" และถูกข้ามอัตโนมัติ (เทียบทั้ง AN และ HN)
  ขอบเขต = **ภายในวันเดียวกัน** บวกหน้าต่างสั้น ๆ 6 ชม. (`robot.dedup_window_hours`)
  > ⚠️ **ห้ามตั้งค่านี้ยาว** เช่น 20 ชม. เพราะยาต้องคีย์ใหม่ทุกวัน — ถ้าหน้าต่างคร่อมข้ามคืน
  > คนที่คีย์ไปเมื่อเย็นวานจะถูกข้ามในรอบเช้าวันนี้ = **คนไข้ไม่ได้ยา**
  > (การรันคร่อมเที่ยงคืนไม่ต้องพึ่งค่านี้ เพราะระบบตรึง "วันของงาน" ไว้ตั้งแต่เริ่มรันอยู่แล้ว)
- **ปลดสถานะ "ต้องตรวจเอง" ได้ 2 ทาง** ตามสิ่งที่เห็นจริงใน HosXP — คนที่จบแบบไม่รู้ผลการบันทึก
  จะถูกล็อกไม่ให้คีย์ซ้ำ เข้าไปตรวจแล้วเลือกปุ่มที่ตรงกับความจริง:

  | เห็นอะไรใน HosXP | กดปุ่ม | ผล |
  |---|---|---|
  | ยา**ยังไม่เข้า** | "ตรวจแล้ว ยายังไม่เข้า → ให้ลองใหม่" | ปลดล็อก กลับไปคีย์ใหม่ได้ |
  | ยา**เข้าไปแล้ว** | "ตรวจแล้ว ยาเข้าแล้ว → ไม่ต้องคีย์ซ้ำ" | นับเป็น "ทำแล้ว" กันคีย์ซ้ำต่อไป |

  > ⚠️ **อย่ากดปุ่มแรกถ้ายาเข้าไปแล้ว** — คนไข้จะได้ยาซ้ำ
  > (เกิดได้จริงเมื่อโรบอทกดบันทึกสำเร็จแล้วสะดุดตอนเก็บกวาดหน้าจอ เช่น run 292)
  > ทั้งสองปุ่มแตะได้เฉพาะสถานะ "ไม่รู้ผล" — คนที่บันทึกสำเร็จจริงถูกกันคีย์ซ้ำไว้เสมอ
- **ตรวจคนไข้ก่อนคีย์**: หลังคีย์ HN ระบบอ่านกรอบ **"ข้อมูลผู้ป่วย"** (คนละกรอบกับที่พิมพ์)
  แล้วเทียบว่า HN ตรง และถ้ามี AN จากฐานข้อมูลก็เทียบ AN ด้วย — ไม่ตรง = ไม่กดเพิ่มยาให้คนนั้น
  ปรับได้ที่ `robot.verify_patient_loaded` (`"strict"` / `"warn"` / `false`)
  > **แนะนำให้ดึงรายชื่อจากฐานข้อมูลเสมอ** เพราะจะได้ AN มาตรวจซ้ำอีกชั้น
  > (AN เป็นเลขที่โรบอทไม่ได้พิมพ์เอง จึงเป็นหลักฐานว่าโหลดถูกคนจริง)
- **ไม่กดปุ่มใส่ dialog ที่ไม่รู้จักเด็ดขาด** (allowlist) — กดให้เฉพาะข้อความที่ตั้งไว้ล่วงหน้าเท่านั้น
  dialog อื่นทั้งหมด = หยุดงาน ปล่อยค้างไว้บนจอให้เภสัชกรอ่านและตัดสินใจเอง
  และคำที่บ่งชี้คำเตือนทางคลินิก (แพ้ยา/Interaction/ซ้ำซ้อน/เกินขนาด/ตั้งครรภ์/ไต/ตับ…) จะหยุดทันทีเสมอ
- **กดยืนยันแบบเจาะจงหน้าต่าง** — ดึง dialog ที่ระบุขึ้นมาเป็นหน้าต่างหน้าสุดก่อนแล้วจึงกด
  และยืนยันว่าปิดจริงด้วย handle ของหน้าต่างนั้น ไม่ใช่เดาจากว่าอะไรอยู่หน้าสุด
- **ตรวจก่อนคลิกทุกครั้งว่าจุดนั้นเป็นปุ่มที่ตั้งใจจริง** — การคลิกใช้พิกัดบนจอ
  ถ้ามีหน้าต่างอื่นบังอยู่ (เช่นเบราว์เซอร์ หรือหน้าต่าง Note) โรบอทจะ**ไม่กด** แล้วรายงานว่าอะไรบังอยู่
  แทนที่จะคลิกมั่วไปโดนหน้าต่างอื่น
- **ไม่ยุ่งกับหน้าต่างของโปรแกรมอื่น** — เช็ค process ของ HosXP ก่อนเสมอ
- **แบ่งระดับความผิดพลาดตามความเสี่ยง**:
  ก่อนกด New พลาดได้ = ข้ามคนนั้น · หลังกด New พลาด = หยุดทั้งงาน (มีชาร์ตค้าง) ·
  หลังกดบันทึกพลาด = หยุดทั้งงานและทำเครื่องหมาย "ต้องตรวจเอง" ไม่คีย์ซ้ำให้อัตโนมัติ
- **กันคีย์ซ้ำเทียบทั้ง AN และ HN** (ตัดศูนย์นำหน้า) — คนเดิมที่มาจากคนละแหล่งข้อมูลก็ยังกันติด
- **โหมดคีย์จริงบังคับตรวจตัวตนแบบเข้ม** ปิดไม่ได้ ต้องเจอ HN/AN บนหน้าจอจึงจะกดเพิ่มยา
- **ไม่เปิด HosXP ซ้อนบานที่สอง** ถ้าหาหน้าต่างไม่เจอแต่โปรแกรมเปิดอยู่ จะฟ้องให้คนไปจัดการก่อน
- **Circuit breaker**: พลาดติดกัน 3 คน พัก 60 วินาที, พลาดติดกัน 6 คน หยุดทั้งงาน
- ปิดหน้าต่าง run.bat ระหว่างรัน → ระบบสั่งหยุดและรอให้คนไข้คนปัจจุบันจบก่อน (สูงสุด 45 วินาที)
- ทุกขั้นตอน รวมข้อความบน popup ทุกใบที่โรบอทกดผ่าน ถูกบันทึกลง log ตรวจย้อนหลังได้

> **ของแต่ละเครื่องแยกกัน** แต่ HosXP เป็นฐานข้อมูลเดียวกันทั้งโรงพยาบาล ดังนั้น

> ถ้าจำเป็นต้องสลับเครื่องหลังรันจริงไปแล้วในวันนั้น ให้ copy `data\ipdaddchart.db`
> จากเครื่องเดิมไปทับที่เครื่องใหม่ก่อนกดเริ่มคีย์ ไม่งั้นเครื่องใหม่จะมองไม่เห็นว่า AN ไหนคีย์ไปแล้ว
> (ตารางประวัติมีคอลัมน์ "เครื่อง" กำกับไว้ให้ตรวจสอบย้อนหลังได้)

## ตัวกรองผู้ป่วยที่ admit อยู่จริง

`ipt.dchdate` ว่าง แปลว่า "ยังไม่ถูกคีย์จำหน่าย" ไม่ได้แปลว่า "ยังนอนอยู่" — ในฐานข้อมูลจริง
มีแถวค้างจากปี 2539 เป็นต้นมาที่ไม่เคยถูกปิด (คนไข้กลับบ้านไปแล้วแต่ไม่ได้คีย์จำหน่าย)
ถ้าปล่อยผ่าน โรบอทจะไปคีย์ยาให้คนที่ไม่ได้นอนอยู่ จึงกรองออกก่อนแสดงรายชื่อ:

| เกณฑ์ | ตัด |
|---|---|
| `max_los_days` (ค่าตั้งต้น 365) | วันนอนเกิน 1 ปี — ใส่ `0` ถ้าไม่ต้องการจำกัด |
| `require_ward` | ไม่มี ward |
| `require_name` | ไม่มีชื่อ-สกุลใน `patient` |
| `drop_superseded_admits` | HN เดียวกันมี admit ที่เริ่มทีหลัง (คนคนเดียวนอนพร้อมกันสองครั้งไม่ได้) |

ปรับได้ที่ `config/settings.json` → `hosxp_db.filters` และหน้าเว็บจะบอกทุกครั้งว่าตัดออกไปกี่คน
ด้วยเหตุผลอะไร เพื่อให้ตรวจสอบได้ว่าไม่ได้ตัดคนที่ควรได้ยาทิ้ง

## คอลัมน์ "รายการยา" คิดมาจากอะไร

นับจำนวนยาที่ `Add Chart F5` จะยกมาให้ ดึงจาก `opitemrece` (`hosxp_db.drug_lookback_days`
ค่าตั้งต้นย้อนหลัง 30 วัน) มีสองจุดที่ทำให้เลขหลอกถ้าเขียน query ตรง ๆ:

- `opitemrece` เก็บ**ยาปนกับเวชภัณฑ์/บริการ** (Echocardiogram, EKG monitor, ค่าบริการห้อง ICU)
  ของพวกนี้ `icode` ขึ้นต้นด้วย 3 และไม่มีใน `drugitems` — ต้อง `JOIN drugitems` เอาเฉพาะยา
- **ห้ามใช้ `MAX(rxdate)` เป็นวันของชาร์ตยา** เพราะคนไข้ส่วนมากมีแถวค่าบริการรายวันของวันนี้แล้ว
  แต่ยังไม่มีชาร์ตยาของวันนี้ (ซึ่งคือเหตุผลที่ต้องรันโปรแกรมนี้) ถ้านับจากวันล่าสุดจะได้ 0
  ทั้งที่มียา continue ค้างอยู่จากเมื่อวาน — ในฐานข้อมูลจริงพลาดแบบนี้ 80 จาก 496 คน
  ต้องหา "วันล่าสุดที่มีรายการยา" ก่อน แล้วค่อยนับยาของวันนั้น (ตัวเลขในเซลล์บอกวันที่กำกับไว้)

ถ้าดึงไม่สำเร็จ คอลัมน์จะขึ้น `—` และหน้าเว็บเตือนไว้ แต่ยังคีย์ยาได้ตามปกติ

## โครงสร้าง

```
app/main.py        FastAPI + API ทั้งหมด (+ single-instance lock)
app/runner.py      คิวงาน 1 งาน/ครั้ง, cancel, circuit breaker, กันคีย์ซ้ำ, ปิดโปรแกรมอย่างสุภาพ
app/robot/         pywinauto: session.py (เชื่อม/login/popup), ipd_addmed.py (ลูปต่อคน)
                   uia_text.py (อ่านข้อความในกล่อง Task Dialog ที่ถามค่าตรง ๆ ไม่ได้)
                   capture.py + dialog_dump.py (เก็บภาพ/โครงสร้าง dialog เป็นหลักฐานตอนหยุด)
app/hosxp_db.py    SELECT ผู้ป่วย admit จาก MariaDB (ipt.dchdate ว่าง) + คำนวณวันนอน + กรองแถวค้าง
app/excel_io.py    อ่าน an/hn จาก Excel
app/db.py          SQLite: runs / logs / completions
app/static/        หน้าเว็บภาษาไทย 3 หน้า
tools/inspect_hosxp.py  สแกน control ของ HosXP ไว้ map ปุ่ม
config/            default_settings.json (แม่แบบ) + settings.json (ต่อเครื่อง, ไม่เข้า git)
```

### settings.json เก็บเฉพาะ "ส่วนที่ต่างจากค่าตั้งต้น"

เดิมไฟล์นี้เก็บสำเนา config **ทั้งก้อน** ทำให้พอโปรแกรมออกกฎ/ค่าใหม่ใน `default_settings.json`
สำเนาเก่าจะทับทิ้งอย่างเงียบ ๆ (เจอจริง 5 ส.ค. 2569 — แก้โปรแกรมแล้วเหมือนไม่มีอะไรเกิดขึ้น หาสาเหตุยากมาก)

ตอนนี้ตอนกดบันทึกในหน้าตั้งค่า ระบบจะเก็บเฉพาะค่าที่ต่างจริง ๆ (เช่นที่อยู่ฐานข้อมูล ชื่อผู้ใช้)
ค่าที่เหลือจะไหลตามตัวโปรแกรมเสมอ — ถ้าเคยมีไฟล์เก่าที่เก็บทั้งก้อน ให้ลบเฉพาะส่วนที่ไม่ได้ตั้งเองออก
